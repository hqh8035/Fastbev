# 分布式训练端口自动分配机制

## 🎯 问题背景

在同一台机器上同时运行多个分布式训练任务时，如果所有任务使用同一个固定端口（如18888），会导致端口冲突，训练无法启动。

## ✅ 解决方案

实现**自动端口分配机制**：主进程自动找到空闲端口，所有GPU子进程共享这个端口。

## 📋 实现原理

### 流程图

```
主进程启动
    ↓
调用 find_free_port() 找到空闲端口（如：35472）
    ↓
设置环境变量：MASTER_PORT=35472
    ↓
mp.spawn() 启动 N 个子进程（继承环境变量）
    ↓
├─ GPU 0 进程 → 读取 MASTER_PORT=35472 → 监听端口 35472
├─ GPU 1 进程 → 读取 MASTER_PORT=35472 → 连接端口 35472
├─ GPU 2 进程 → 读取 MASTER_PORT=35472 → 连接端口 35472
└─ GPU 3 进程 → 读取 MASTER_PORT=35472 → 连接端口 35472
    ↓
所有进程成功通信 ✅
```

### 关键代码

**主进程（main函数）**:
```python
if args.distributed:
    n_gpus = torch.cuda.device_count()
    
    # 在主进程中找到空闲端口
    if "MASTER_PORT" not in os.environ:
        free_port = find_free_port()
        os.environ["MASTER_PORT"] = str(free_port)
        print(f"Auto-allocated MASTER_PORT: {free_port}")
    
    # 启动所有子进程（继承环境变量）
    mp.spawn(
        train_worker,
        args=(n_gpus, cfg, True, args.resume),
        nprocs=n_gpus,
        join=True,
    )
```

**子进程（Trainer类）**:
```python
def _setup_distributed(self):
    # 所有进程从环境变量读取同一个端口
    master_port = int(os.environ.get("MASTER_PORT", "18888"))
    
    os.environ["MASTER_ADDR"] = "localhost"
    os.environ["MASTER_PORT"] = str(master_port)
    
    dist.init_process_group(
        backend="nccl",
        rank=self.rank,
        world_size=self.world_size,
    )
```

**端口查找函数**:
```python
def find_free_port():
    """查找系统中的空闲端口"""
    with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as s:
        s.bind(("", 0))  # 绑定到任意空闲端口
        s.listen(1)
        port = s.getsockname()[1]  # 获取系统分配的端口号
    return port
```

## ⚠️ 常见错误及解决

### 错误1: 每个进程使用不同端口

**错误代码**（已修复）:
```python
# ❌ 错误：每个进程PID不同，导致计算出不同端口
master_port = 29500 + hash(os.getpid()) % 1000

# GPU 0 (PID=12345) → 端口 29723
# GPU 1 (PID=12346) → 端口 29456  ❌ 无法通信
# GPU 2 (PID=12347) → 端口 29189  ❌ 无法通信
```

**错误信息**:
```
[c10d] TCP client failed to connect/validate to host localhost:29858
```

**解决方案**: 使用环境变量在进程间共享端口号

### 错误2: 端口被占用

**错误信息**:
```
[E socket.cpp:435] [c10d] Socket creation failed: Address already in use
```

**原因**: 另一个训练任务正在使用该端口

**解决方案**: 
- 自动分配模式会自动避免（推荐）
- 或手动指定不同端口：`MASTER_PORT=19999 bash shell_scripts/01_train.sh`

## 🔧 技术细节

### 环境变量继承

`mp.spawn()` 启动的子进程会**自动继承父进程的环境变量**：

```python
# 主进程
os.environ["MASTER_PORT"] = "35472"
mp.spawn(train_worker, ...)

# 子进程自动获得
os.environ["MASTER_PORT"]  # → "35472"
```

### find_free_port() 原理

```python
def find_free_port():
    with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as s:
        s.bind(("", 0))  # 参数 0 表示让系统分配任意空闲端口
        s.listen(1)
        port = s.getsockname()[1]  # 获取系统实际分配的端口号
    return port  # socket关闭，端口释放，可供使用
```

**注意**: 
- 在 `find_free_port()` 返回后，socket被关闭，端口被释放
- 在极短时间内（毫秒级），其他进程可能占用该端口
- 但在实际使用中，这个时间窗口非常小，几乎不会发生冲突
