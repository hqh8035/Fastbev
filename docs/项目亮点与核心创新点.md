# Nova FastBEV 技术文档

# 一、项目亮点与核心创新点

## 1. 核心思路：单目相机实现 BEV 3D 感知

用**单张图像**（非多视角环视）完成 BEV 空间的 3D 检测 + 语义分割，面向低成本嵌入式部署场景（如 golf 车/采集车）。通过显式几何投影（相机内参 → grid_sample）将 2D 特征"拉"到 3D 体素空间，无需 Transformer 的隐式注意力，推理速度快且可量化部署。

## 2. DINOv3 双流 Backbone（最大创新）

### 2.1 DINOv3、ViT、ConvNeXt 三者的关系

**DINOv3 不是一个网络结构，而是 Meta（Facebook AI）的自监督预训练方法**——让模型不看人工标注，只通过 16.8 亿张图片自己学会理解视觉世界。ViT 和 ConvNeXt 是两种不同架构的 Backbone 网络，都用 DINOv3 方法预训练过，**权重是官方公开发布的，直接下载即可使用**。

类比：DINOv3 = "教学方法"，ViT = "用这种方法教出来的 Transformer 学生"，ConvNeXt = "同一方法教出来的 CNN 学生"。本项目同时用两个学生的能力，但不修改它们——只接上自己设计的轻量处理层。

### 2.2 什么是"双流"？为什么要双流？

想象你看一张照片时有两种方式理解它：
- **全局理解**："这是一个十字路口，有车有人" → 这是 **ViT** 擅长的
- **局部细节**："这个轮胎的花纹、车牌的边缘" → 这是 **ConvNeXt** 擅长的

单独用任何一个都有缺陷：ViT 看得懂全局但丢细节，ConvNeXt 抓得住细节但缺全局语义。本项目的创新是**同时用两个官方预训练好的大模型（冻结参数），各取所长，再融合**。

### 为什么原版不用双流，而本项目要？

核心原因是**单目 vs 多视角**带来的信息量差异：

| | 原版（6 摄像头环视） | 本项目（1 个前视摄像头） |
|--|--|--|
| 信息量 | 6 张图 360° 互补，冗余度高 | 单张图，信息稀缺 |
| 对特征质量的要求 | 中等即可，多图兜底 | 极高，一张图必须提取到位 |
| Backbone 策略 | 轻量 CNN ×6，省算力 | 冻结大模型 ×1，靠预训练知识补信息 |

原版有 6 个摄像头互相补充，轻量 Backbone 就够用；而且大模型 ×6 显存和推理时间不可接受。本项目只有一个前视摄像头，信息极度有限，远处物体小、没有多视角交叉验证，必须靠大模型在 16.8 亿张图上积累的视觉知识来弥补。

**多视角靠数量取胜，单目靠质量取胜。**

### 2.2 两个分支各自做什么？

**ViT 分支**（Vision Transformer，参数量约 630M）：

ViT 的工作方式类似"开会讨论"——把图像切成很多小块（patch），让所有小块互相"交流"（自注意力机制），最终每个小块都知道整张图在发生什么。它擅长**全局理解**：判断场景类型、物体之间的关系。但缺点是分辨率低（只有 1/16），丢失了精细的边缘和纹理信息。

此外，ViT 还有一个特殊的 **class token**——可以理解为"会议纪要"，浓缩了整张图的全局语义。本项目把 class token 复制后拼接到每个 patch token 上，让每个位置同时拥有"我是什么"和"我在全局中扮演什么角色"的信息。

**ConvNeXt 分支**（现代卷积网络，参数量约 200M）：

ConvNeXt 的工作方式类似"显微镜逐级放大"——逐层缩小分辨率，每一层用卷积核在局部区域滑动，捕捉不同大小的纹理和边缘。它输出 4 个尺度的特征图（1/4、1/8、1/16、1/32），从精细边缘到大范围结构都能覆盖。擅长**局部细节**，但缺乏跨图像的全局推理能力。

**关键：两个模型都是冻结的（frozen）**，参数不更新，只当"特征提取器"使用，用 bfloat16 半精度推理节省显存。这保证了预训练在 16.8 亿张图片上学到的通用视觉知识不被小数据集破坏。

### 2.3 Backbone 全过程

#### 阶段一：两个冻结大模型并行提取原始特征

输入图像同时送入两个模型（冻结、bfloat16 半精度，不计算梯度）：

```
输入图像 [B, 3, 816, 960]
      │
      ├──→ ViT-H（冻结）
      │      取第 15/23/31 层中间输出，每层都是 1/16 分辨率
      │      每层输出 patch_token + class_token，拼接后通道 2560
      │      → 3 组特征 [B, 2560, 51, 60]
      │
      └──→ ConvNeXt-L（冻结）
             取 4 个 stage 输出，分辨率逐级缩小
             Stage0: [B, 192, 204, 240]    (1/4)
             Stage1: [B, 384, 102, 120]    (1/8)
             Stage2: [B, 768, 51, 60]      (1/16)
             Stage3: [B, 1536, 26, 30]     (1/32)
```

关于 class token：ViT 除了每个小块的特征（patch token），还输出一个浓缩全图语义的 class token。本项目把 class token 复制后拼接到每个 patch token 上（1280+1280=2560），让每个位置同时拥有"我是什么"和"全局在发生什么"的信息。

#### 阶段二：投影到统一通道数（可训练）

两路特征通道数不同，通过投影层统一到 256 通道：

```
ViT 3层（各 2560ch）→ 上采样+投影：
   层0 → deconv(×4上采样) → [B, 256, 204, 240]  对齐到 1/4
   层1 → deconv(×2上采样) → [B, 256, 102, 120]  对齐到 1/8
   层2 → 1×1 conv         → [B, 256, 51, 60]    保持 1/16

ConvNeXt 4层 → 各用 3×3 conv 投影：
   Stage0 (192ch) → [B, 256, 204, 240]   (1/4)
   Stage1 (384ch) → [B, 256, 102, 120]   (1/8)
   Stage2 (768ch) → [B, 256, 51, 60]     (1/16)
   Stage3 (1536ch)→ [B, 256, 26, 30]     (1/32)
```

ViT 输出全是 1/16（patch_size=16），需要上采样到不同尺度和 ConvNeXt 对齐。

#### 阶段三：自底向上逐级融合（可训练）

从最深层开始，每级通过 FusionBlock 把三路信息合并：

```
第1级：ConvNeXt(1/32) 上采样 + ViT(1/16) + ConvNeXt(1/16)
       → FusionBlock[0] → 融合结果(1/16)

第2级：融合结果(1/16) 上采样 + ViT(1/8) + ConvNeXt(1/8)
       → FusionBlock[1] → 融合结果(1/8)

第3级：融合结果(1/8) 上采样 + ViT(1/4) + ConvNeXt(1/4)
       → FusionBlock[2] → 最终输出(1/4)
```

每个 FusionBlock 内部：三路拼接 → 1×1 Conv 压缩 → 残差块增强（1×1→3×3→1×1）→ 1×1 Conv 输出。

#### 最终输出

```
[B, 256, 204, 240]  —— 1/4 分辨率，融合了 ViT 全局语义 + ConvNeXt 局部细节
```

这个特征后续分两路使用：
- 直接送入 `seg_grass_head` → 2D 图像空间做树枝分割
- 送入 `proj_to_bev` + `grid_sample` → 投影到 BEV 空间做 3D 检测

### 2.5 为什么这是最大创新？

| 对比项 | 原版 FastBEV | 本项目 |
|--------|-------------|--------|
| Backbone | 轻量 MobileNetV2 风格 | DINOv3 ViT-H + ConvNeXt-L |
| 参数量 | ~5M（全部可训练） | ~830M 冻结 + ~10M 可训练 |
| 特征质量 | 从头学，受限于数据量 | 继承 DINOv3 在 16.8 亿图像上的预训练知识 |
| 训练成本 | 全网络端到端 | 只训练投射层和 head，收敛极快 |
| 适用场景 | 大数据量时有优势 | 小数据量也能获得高质量特征 |

核心价值：**用大模型的"眼力"（冻结权重）+ 小模型的"快腿"（轻量可训练部分）**，在有限训练数据下获得远超从头训练的特征质量。

## 3. BEV Neck 复用 ConvNeXt 结构

### 3.1 什么是 Neck？它在网络中的角色

整个网络可以类比为人的"感知系统"：

```
Backbone（眼睛）→ Neck（大脑皮层）→ Head（嘴巴输出结论）
  提取原始特征      整合、增强特征       输出最终预测
```

BEV Neck 的输入是从 3D 体素压缩来的 `[B, 160, 320, 320]`（10 层高度特征拼接），它的任务是把这些"粗糙的拼凑"变成"精炼的理解"——既能看到近处的小物体，也能理解远处的大场景。

### 3.2 为什么要"复用" ConvNeXt？

正常做法是从零开始训练一个 Neck 网络。但问题是：
- BEV 特征本质上也是一张"图片"（鸟瞰图），和自然图像有类似的局部纹理模式
- DINOv3 的 ConvNeXt 已经在 16.8 亿张图片上学会了"怎么从图片中提取多尺度信息"
- 这个能力可以直接迁移过来！

所以本项目**直接把预训练 ConvNeXt 的核心组件搬过来当 BEV Neck 用**，相当于"站在巨人肩膀上"处理 BEV 特征。

### 3.3 复用了 ConvNeXt 的哪些部分？

```python
convnext_model = get_dinov3_model('dinov3_convnext_base')  # 加载预训练模型

# 复用这两个核心组件（带预训练权重）：
self.downsample_layers = convnext_model.downsample_layers[1:4]  # 下采样层（缩小分辨率）
self.stages = convnext_model.stages                              # 特征处理层（4个阶段）
```

- **stages**：ConvNeXt 的核心模块，包含多个 ConvNeXt Block（深度可分离卷积 + LayerNorm + GELU），负责在当前分辨率下充分学习特征
- **downsample_layers**：把特征图缩小一半（类似池化），让网络看到更大范围

### 3.4 Dinov3BEVNeck 完整工作流程

```
输入 [B, 160, 320, 320]（体素拼接后的BEV特征）
       │
       ↓ proj (1×1 Conv): 160 → 128（通道压缩）
       │
       ↓ stage[0]（ConvNeXt Blocks，预训练权重）
       │
       ├─ x_1x [B, 128, 320, 320] ──→ 1×1 Conv ──→ [B, 128, 320, 320] ─┐
       │                                                                   │
       ↓ downsample[0]（预训练权重，缩小2倍）                              │
       ↓ stage[1]                                                          │
       │                                                                   │
       ├─ x_2x [B, 256, 160, 160] ──→ deconv(×2上采样) → [B, 128, 320, 320] ─┐
       │                                                                   │   │
       ↓ downsample[1]（缩小2倍）                                          │   │
       ↓ stage[2]                                                          │   │
       │                                                                   │   │
       ├─ x_3x [B, 512, 80, 80] ───→ deconv(×4上采样) → [B, 128, 320, 320] ──┐
       │                                                                   │   │ │
       ↓ downsample[2]（缩小2倍）                                          │   │ │
       ↓ stage[3]                                                          │   │ │
       │                                                                   │   │ │
       └─ x_4x [B, 1024, 40, 40] ──→ deconv(×8上采样) → [B, 128, 320, 320]   │ │
                                                                           │   │ │ │
                                                              cat 四路 ←───┘───┘─┘─┘
                                                                           ↓
                                                              [B, 512, 320, 320]
                                                                           ↓
                                                              3×3 Conv 融合
                                                                           ↓
                                                              [B, 128, 320, 320] → 输出给 Head
```

### 3.5 为什么要多尺度？用生活类比

假设你是一个鸟瞰视角的无人机：
- **x_1x（320×320）**：你在 10m 高空，能看清每辆车的形状 → 检测小物体
- **x_2x（160×160）**：你在 20m 高空，能看到一个车队 → 中等范围关系
- **x_3x（80×80）**：你在 40m 高空，能看到整个路口 → 大范围上下文
- **x_4x（40×40）**：你在 80m 高空，能看到整个街区 → 全局布局

最终把四个高度看到的信息全部汇总，让网络既不漏小物体，也理解全局关系。

### 3.6 对比：从头训练 vs 复用预训练

| | 从头训练 BEV Neck | 复用 ConvNeXt（本项目） |
|--|--|--|
| 初始状态 | 随机权重，什么都不知道 | 已经学会多尺度特征提取 |
| 收敛速度 | 慢，需要大量 BEV 数据 | 快，预训练知识直接可用 |
| 最终效果 | 受限于 BEV 训练数据量 | 即使数据少也能有好效果 |
| 风险 | 容易过拟合 | 预训练正则化，更稳定 |

一句话总结：**BEV 特征本质上也是一张"图"，处理图的好方法（ConvNeXt）可以直接拿来用，不必重新发明轮子。**

## 4. 多任务统一框架：检测 + 分割

单网络同时输出：
- **3D 目标检测**（heatmap center + offset + height + lwh + yaw，支持 gaussian/standard 两种 GT 格式）
- **语义分割**（树枝/车道线等），且分割直接在 2D feature map 上出（`seg_grass_head` 接在 backbone 后），不经过 BEV 投影——合理利用了"分割是 2D 任务"的先验

## 5. 混合数据训练策略

通过 `with_camera_intrinsics` / `with_seg_label` 标志位，支持不同数据源只提供部分标注：
- 有内参的数据才计算 det loss
- 有分割标签的数据才计算 seg loss

这使得 Waymo（有3D标注）和六分自有数据（可能只有分割标注）可以混合训练。

## 6. 量化部署友好设计

- `torch.clip` + `numpy` 转换绕过量化编译算子限制
- ONNX 导出路径独立（`export` 方法）
- 支持 Horizon（地平线芯片）量化导出 (`horizon_nn.api`)
- 固定 `target_size`、预计算 `sampling_coords` 用于部署时消除动态 shape

## 7. Yaw 角度预测的 Cosine Similarity Loss

### 7.1 什么是 Yaw 角？

Yaw（偏航角）就是物体在鸟瞰图上的**朝向角度**——车头朝哪个方向。

```
        ↑ 0°
        |
  270° ←·→ 90°
        |
        ↓ 180°
```

比如一辆车面朝正前方是 0°，朝右是 90°，朝后是 180°。

### 7.2 为什么不直接预测角度值？

直觉上可以让网络直接输出一个数（比如 73.5°），然后用 L1 Loss 算误差。但有个严重问题：

**角度的周期性**：359° 和 1° 其实只差 2°，但数值上差了 358°。直接回归角度值会让网络对边界处困惑。

### 7.3 解决方案：预测 sin 和 cos

把角度 θ 分解为两个值：
```
sin(θ) 和 cos(θ)
```

这两个值组成一个单位圆上的点 `(cos θ, sin θ)`：

```
         sin
          ↑   · (cos30°, sin30°) = (0.87, 0.5)
      1   |  /
          | / ← 角度θ
    ------+------→ cos
          |
     -1   |
```

无论角度怎么变，`(cos θ, sin θ)` 总是平滑变化，没有跳变问题。

### 7.4 为什么 L1 Loss 不适合 sin/cos？

如果用 L1 Loss 分别约束 sin 和 cos：
```
L1_loss = |sin_pred - sin_gt| + |cos_pred - cos_gt|
```

问题：网络可能输出 sin=0.8, cos=0.9，但 0.8²+0.9²=1.45 ≠ 1，**不在单位圆上**！这意味着预测的 (sin, cos) 不对应任何合法角度。

### 7.5 Cosine Similarity Loss 怎么解决？

**核心思想**：不关心向量的长度，只关心方向是否对齐。

```python
# 第一步：归一化到单位圆（强制 sin²+cos²=1）
yaw_pred_norm = F.normalize(yaw_pred, p=2, dim=2)
yaw_gt_norm = F.normalize(yaw_gt, p=2, dim=2)

# 第二步：计算余弦相似度（两个单位向量的点积）
cos_sim = (yaw_pred_norm * yaw_gt_norm).sum(dim=2)
# cos_sim = cos(pred_angle - gt_angle)
# 完全对齐时 = 1，完全相反时 = -1

# 第三步：转为 loss（越小越好）
yaw_loss = 1.0 - cos_sim
# 完全对齐时 loss = 0，完全相反时 loss = 2
```

### 7.6 几何直觉

```
情况1：预测准确                情况2：预测偏了45°           情况3：完全反向
    gt ↑                           gt ↑                        gt ↑
       |                              |  ╱ pred                    |
       | pred                         | ╱                          |
       ↑                              ╱                            ↓ pred
  cos_sim = 1.0                  cos_sim = 0.71               cos_sim = -1.0
  loss = 0                       loss = 0.29                  loss = 2.0
```

**本质**：Cosine Similarity 度量的是两个方向之间的"角度差"，而不是坐标差。它天然理解角度的几何含义。

### 7.7 对比总结

| | 直接回归角度 + L1 | sin/cos + L1 | sin/cos + Cosine Similarity（本项目）|
|--|--|--|--|
| 周期性问题 | 有（359° vs 1°跳变） | 无 | 无 |
| 单位圆约束 | 不适用 | 不保证 sin²+cos²=1 | 归一化后强制满足 |
| 几何含义 | 数值距离≠角度距离 | 数值距离≈角度距离 | 直接度量角度差 |
| 梯度行为 | 边界处梯度混乱 | 正常 | 平滑且方向正确 |

# 二、数据输入流程

## 1. 整体数据流

```
标注JSON文件(cam_intrinsic + cam_bbox_3d)
         ↓
WaymoBEVDataset.__getitem__()
         ↓  输出 sample dict
Transform (Resize → Augment → ToTensor → Normalize)
         ↓  调整内参以匹配缩放后图像
collate_fn → batch dict
         ↓
FastBEV.forward(data_dict)
  ├─ data_dict['image']              → Backbone提特征
  └─ data_dict['camera_intrinsics']  → 计算 sampling_coords (2D→3D投影)
```

## 2. 各输入的具体来源和处理

| 输入 | 来源 | 处理方式 |
|------|------|----------|
| **图像** | `cv2.imread(image_file)` → Resize到(816,960) → 归一化 | 输入Backbone提特征，shape=[B,3,H,W] |
| **相机内参** | 标注JSON的`cam_intrinsic`字段(3×3矩阵) | Resize时同步缩放fx/fy/cx/cy → 送入`_compute_sampling_coordinates()` |
| **外参(extrinsic)** | **不使用** | 标注已在相机坐标系下，`cam_bbox_3d`直接是相机系坐标 |
| **ego pose** | **不使用** | 仅在数据预处理脚本(nuScenes)中用于坐标转换，训练/推理时不需要 |

## 3. 图像特征如何投影到 Voxel 空间

核心思想是**反向投影**：不是从图像出发去找3D，而是从3D体素空间出发，通过内参找回图像上对应的像素位置，再采样特征。

### Step 1: 构建 3D 体素网格 (`_get_bev_grid`)

在相机坐标系下，构建 BEV 的 XZ 平面网格：

```
X: [-16, 16] → 320 个格点（每格 0.1m）
Z: [0, 32]   → 320 个格点（每格 0.1m）
Y: [-2, 3]   → 10 个高度层（每层 0.5m）
```

总共 320 × 320 × 10 = **1,024,000 个体素点**。

### Step 2: 逐高度层投影到图像 (`_compute_sampling_coordinates`)

对每个高度层 y_height（共10层），将所有 (x, y_height, z) 点通过针孔模型投影到图像：

```python
# model/fastbev.py: _project_to_image()
u = fx * x / z + cx    # 图像列坐标
v = fy * y / z + cy    # 图像行坐标

# 归一化到[-1,1]用于 grid_sample
u_norm = 2.0 * (u / image_width) - 1.0
v_norm = 2.0 * (v / image_height) - 1.0
```

输出：`sampling_coords` shape = `[B, 10, 320, 320, 2]`

### Step 3: 采样图像特征到体素位置 (`_sample_features_with_coords`)

对每个高度层 y：
1. 用独立的 1×1 Conv (`proj_to_bev[y]`) 将 backbone 特征从高维投影到 16 通道
2. 用 `F.grid_sample` 按照 `sampling_coords[:, y]` 从 feature map 上做双线性插值采样

```python
cur_features = self.proj_to_bev[y](features)    # [B, 16, H_feat, W_feat]
sampled = F.grid_sample(cur_features, coords)    # [B, 16, 320, 320]
```

### Step 4: 拼接高度层——3D Voxel 压缩为 2D BEV

10 层各 16 通道沿通道维度拼接：

```
[B, 16, 320, 320] × 10 层  →  cat dim=1  →  [B, 160, 320, 320]
```

**压缩本质**：高度维度（Y轴）通过 channel concat 被"折叠"进通道维度，空间上只保留 X-Z 平面（即鸟瞰视角）。后续 BEV Neck 的卷积隐式学习如何从 160 通道中融合不同高度的信息。

### Step 5: BEV Neck 特征融合 (`bev_fusion`)

拼接后的 `[B, 160, 320, 320]` 送入 BEV Neck，输出 `[B, 128, 320, 320]` 的高质量 BEV 特征。

**Dinov3BEVNeck 结构**（默认使用）：

```
输入 [B, 160, 320, 320]
       │
       ├─ proj(1×1 Conv): 160 → 128
       │
       ├─ stage[0] → x_1x [B, 128, 320, 320]  ──→ upsample[0](1×1) ──→ [B, 128, 320, 320]
       │
       ├─ downsample → stage[1] → x_2x [B, 256, 160, 160] → upsample[1](deconv ×2) → [B, 128, 320, 320]
       │
       ├─ downsample → stage[2] → x_3x [B, 512, 80, 80]   → upsample[2](deconv ×4) → [B, 128, 320, 320]
       │
       └─ downsample → stage[3] → x_4x [B, 1024, 40, 40]  → upsample[3](deconv ×8) → [B, 128, 320, 320]
                                                                              │
                                                                    cat 4个尺度 [B, 512, 320, 320]
                                                                              ↓
                                                                    fusion(3×3 Conv) → [B, 128, 320, 320]
```

这是一个 **FPN（特征金字塔）** 结构：先多尺度下采样提取不同感受野的特征，再全部上采样回原始分辨率后 concat + 融合。

**BevNeck 结构**（轻量版，MobileNetV2 风格）：

```
输入 [B, 160, 320, 320]
       │
       ├─ conv_1x: [B, 32, 320, 320]
       ├─ conv_2x: [B, 64, 160, 160]
       ├─ conv_4x: [B, 96, 80, 80]
       └─ conv_8x: [B, 96, 40, 40]
                │
                └─ 逐级上采样 + skip fusion → [B, 128, 320, 320]
```

### 完整流程示意图

```
Backbone特征 [B, C, H/4, W/4]
       │
       ├── proj_to_bev[0](1×1 Conv) → grid_sample(coords[:,0]) → [B,16,320,320]  (y=-1.75m)
       ├── proj_to_bev[1](1×1 Conv) → grid_sample(coords[:,1]) → [B,16,320,320]  (y=-1.25m)
       ├── ...
       └── proj_to_bev[9](1×1 Conv) → grid_sample(coords[:,9]) → [B,16,320,320]  (y=+2.75m)
                                                                        │
                                                                   cat dim=1
                                                                        ↓
                                                          3D Voxel [B, 160, 320, 320]
                                                           (高度维折叠进通道维)
                                                                        ↓
                                                                    BEV Neck
                                                           (多尺度下采样 + FPN融合)
                                                                        ↓
                                                           2D BEV [B, 128, 320, 320]
                                                                        ↓
                                                                 det3d_head
                                                                        ↓
                                                              [B, 27, 320, 320]

Backbone特征 [B, 128, H/4, W/4]  (同一份特征，分割分支不经过BEV投影)
                    ↓
              seg_grass_head
                    ↓
            [B, 1, H/4, W/4]
```

### Step 6: 检测与分割 Head

两个 Head 结构相同（两层 1×1 Conv + ReLU），但**输入来源和工作空间不同**：

```python
# det3d_head: BEV空间 → 3D检测
det3d_head = nn.Sequential(
    nn.Conv2d(128, 128, 1),   # 特征变换
    nn.ReLU(),
    nn.Conv2d(128, 27, 1)     # 输出 27 通道
)

# seg_grass_head: 图像空间 → 2D分割
seg_grass_head = nn.Sequential(
    nn.Conv2d(128, 128, 1),   # 特征变换
    nn.ReLU(),
    nn.Conv2d(128, 1, 1)      # 输出 1 通道(树枝前景概率)
)
```

| | det3d_head | seg_grass_head |
|--|--|--|
| **输入来源** | BEV Neck 输出 `[B, 128, 320, 320]` | Backbone 输出 `[B, 128, H/4, W/4]` |
| **工作空间** | BEV 鸟瞰空间（XZ平面） | 2D 图像空间 |
| **输出通道** | 27 = 9属性 × 3类 | 1（树枝二分类） |
| **输出含义** | center(1) + height(1) + offset(2) + lwh(3) + yaw(2) per class | 像素级前景概率 |

**det3d_head 输出 27 通道的解码方式**：

```
通道 [0:9]   → vehicle:  center(1) + offset(2) + height(1) + lwh(3) + yaw(2)
通道 [9:18]  → person:   center(1) + offset(2) + height(1) + lwh(3) + yaw(2)
通道 [18:27] → cyclist:  center(1) + offset(2) + height(1) + lwh(3) + yaw(2)
```

**设计意图**：
- det3d_head 放在 BEV 空间：3D 检测需要在鸟瞰视角下回归物体中心和尺寸，BEV 天然适合
- seg_head 放在 2D 图像空间：树枝分割是纯像素级任务，不需要投影到 BEV，直接在高分辨率 feature map 上做效果更好且省去投影计算

### 关键设计点

- **每层独立 1×1 Conv**：不同高度看到的语义不同（地面 vs 车顶 vs 天空），用独立投影分开学习
- **反向投影而非正向投影**：保证 BEV 空间每个位置都有值，无空洞
- **高度压缩 = channel concat**：不做显式 pooling/attention，而是让后续卷积隐式学习高度维融合，简单高效
- **BEV Neck 复用预训练权重**：Dinov3BEVNeck 直接加载 ConvNeXt 预训练的 downsample + stage 参数，加速收敛
- **`padding_mode='zeros'`**：落在图像外的体素自动填零，不影响可见区域
- **部署时固定 `sampling_coords`**：若内参不变，坐标可预计算为常量，推理时省去投影计算

## 4. 为什么不需要外参和 ego pose？

本项目是**单目前视相机**方案，所有3D标注(`cam_bbox_3d`)已经在相机坐标系下表示：
- X轴：向右（左右偏移）
- Y轴：向下（高度）
- Z轴：向前（深度）

BEV空间直接定义在相机坐标系的XZ平面上，因此只需内参即可完成"图像特征 → BEV空间"的投影，无需世界坐标系变换。

## 5. `with_camera_intrinsics` 标志位的作用

```python
# 若标注文件缺失（无内参），置为全-1矩阵，标志位为False
camera_intrinsics = np.ones([3, 3]) * -1
with_camera_intrinsics = False

# loss计算时：只有有内参的样本才计算检测loss
det3d_gt = det3d_gt[with_camera_intrinsics]
det3d_pred = det3d_pred[with_camera_intrinsics]
```

这使得混合数据训练成为可能——没有3D标注的数据仍可训练分割分支。
