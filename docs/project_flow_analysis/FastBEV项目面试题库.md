# FastBEV 项目面试题库

这份文档把 `FastBEV` 项目的核心考点整理成一套可直接用于模拟面试的问题清单，默认场景是：

- 你是多模态 / 自动驾驶感知 / 3D 视觉方向实习生候选人
- 面试官围绕这个仓库追问你的项目理解、建模思路和工程取舍
- 题目以“为什么这样设计”优先，而不是只问“代码里写了什么”

建议使用方式：

- 先顺着第一部分做 3 到 5 分钟项目介绍
- 再按数据层、训练层、模型层分块练习
- 最后重点准备“为什么不用别的方案”和“你做过哪些改动”

---

## 一、项目总览题

### 1. 开场介绍题

1. 请你先整体介绍一下这个 `FastBEV` 项目，它要解决什么问题？
2. 这个项目的输入是什么，输出是什么？
3. 它和普通 2D 检测 / 分割项目相比，最大的不同在哪里？
4. 从单张前视图到最终的 BEV 检测结果，中间主链路是什么？
5. 这个项目为什么能同时做 3D 检测和分割，这两个任务共享了哪些模块？
6. 如果只用一句话概括这个项目的核心思想，你会怎么说？

### 2. 面试官常见追问

1. 为什么这个项目适合归类为“多模态”或“几何感知”项目，而不是普通 CNN 项目？
2. 这个项目里最体现你理解深度的一个模块是什么？
3. 如果让你给一个没看过代码的人解释这个项目，你会优先讲数据、训练还是模型？为什么？
4. 这个项目的核心难点更偏数据、几何还是优化？请给出你的判断。

## 二、数据层题

### 3. 数据组织与样本管理

1. 为什么训练集不是直接扫目录，而是通过 `annotations_file` 管理样本？
2. 这种“路径清单式”数据管理相比直接扫目录、JSON 索引、数据库管理分别有什么优缺点？
3. 如果训练过程中不断增加 hard case，你觉得 `annotations_file` 方案为什么更适合持续迭代？
4. 你怎么保证一次训练到底用了哪些样本是可追溯、可复现的？

### 4. 图像与标签配对

1. 为什么标签路径是由图片路径反推，而不是单独维护 `image -> label` 的映射表？
2. 这种强目录约定在工程上带来了什么好处？
3. 这种做法的代价是什么？如果目录规范被破坏，会出现什么问题？
4. 如果后续要支持更多标签类型，这种路径反推机制是否还能扩展？

### 5. 缺标样本与多任务监督

1. 为什么缺标样本没有直接丢弃，而是在 loss 层按任务动态屏蔽？
2. `with_camera_intrinsics` 和 `with_seg_label` 这类标记在训练里起到了什么作用？
3. 为什么这种做法比“只保留全标注样本”更适合工业数据？
4. 如果检测标签和分割标签来自不同来源，这种设计会带来哪些训练收益？
5. 这种动态屏蔽会不会引入 batch 内监督不均衡？你怎么理解这个风险？

### 6. FOV 与监督一致性

1. 为什么要先做 FOV 过滤，再生成检测 GT？
2. 如果不做 FOV 过滤，会给单目前视 BEV 训练带来什么伪监督？
3. 这个项目为什么选择“框中心投影 + 图像边界检查”这种轻量过滤，而不是更重的可见性建模？
4. 你觉得这种过滤标准有哪些局限？在哪些场景下可能过于粗糙？

### 7. 检测 GT 设计

1. 为什么中心点 GT 不是纯 one-hot，而是正中心为 `1`、周围一圈为 `-1`？
2. 这种 ignore ring 相比高斯热图和纯 one-hot 的折中点是什么？
3. 这种设计如何缓解正负样本极不平衡的问题？
4. 如果你发现中心点学习不稳定，你会先怀疑 GT 设计、loss 形式还是采样策略？

### 8. 分割标签与分辨率对齐

1. 为什么分割 GT 在数据层就缩放到 head 分辨率，而不是在 loss 里再做 resize？
2. 这种“前移对齐”的设计会给训练链路带来什么好处？
3. 如果 GT 保持原分辨率，loss 里再对齐，会有哪些常见坑？
4. 这种方式对部署一致性有没有帮助？为什么？

### 9. 几何一致性

1. 为什么 resize 图像时必须同步修改相机内参？
2. 如果图像尺寸变了但 `fx / fy / cx / cy` 没改，会具体影响哪些后续步骤？
3. 为什么这个问题不能简单交给网络自己学补偿？
4. 你怎么理解“几何一致性应该由预处理保证，而不是交给网络去猜”这句话？

### 10. 多来源数据混训

1. `UnifiedBEVDataset` 解决的核心问题是什么？
2. 为什么多数据源混训最好做成框架能力，而不是每次在训练脚本里临时拼接？
3. 配置里的 `weight` 在多数据集训练里起到了什么作用？
4. 为什么 `waymo / pedestrian / corner` 这类数据要显式分开配置，而不是离线混成一个大列表？
5. 如果要新接入一份专项数据集，你觉得这个项目的接入成本大概落在哪些地方？

## 三、训练层题

### 11. 训练主节拍

1. 为什么这个项目更偏 step-based 训练，而不是传统 epoch-based 训练？
2. 在多数据源混训和加权采样场景下，为什么 epoch 的语义会变弱？
3. `MAX_ITERS / SAVE_FREQ / PRINT_FREQ` 这种设计反映了什么工程取向？

### 12. 分布式采样

1. 分布式场景下做加权采样为什么容易出问题？
2. 为什么要单独考虑每个 rank 的随机性？
3. 如果所有 rank 用完全一致的采样逻辑，最可能出现什么问题？
4. 这个项目没有追求特别复杂的 sampler，而是追求“够用且稳定”，你怎么看这种取舍？

### 13. Dataloader 稳定性

1. 为什么多卡训练时要主动压低 dataloader worker 数？
2. 这背后主要是在规避算力瓶颈，还是在规避系统稳定性问题？
3. `min(NUM_WORKERS // world_size, 2)` 这类保守策略说明了什么？
4. 如果你遇到训练 hang 住，你会先排查模型还是数据加载？

### 14. 分布式启动与环境问题

1. 为什么要自动分配 `MASTER_PORT`？
2. 同一台机器并行起多个训练任务时，最常见的分布式问题是什么？
3. 这类问题为什么应该由脚本层自动化处理，而不是交给用户手动规避？

### 15. EMA 设计

1. 为什么 EMA 要在 DDP 包装前创建？
2. 如果先 DDP 再复制模型做 EMA，可能带来哪些结构问题？
3. EMA 为什么不只更新参数，还要同步 buffer？
4. 参数做 EMA、buffer 直接 copy，这种组合为什么更合理？
5. 你怎么向面试官解释 EMA 对训练稳定性和最终推理效果的帮助？

### 16. 稳定训练策略

1. 这个项目为了让训练更稳定，做了哪些组合拳？
2. 为什么要降低学习率并加 warmup？
3. 为什么要做梯度裁剪？它主要在防什么？
4. 为什么用 cosine annealing，而不是更激进的调度策略？
5. `weight_decay` 的提升在这个项目里更多是在防过拟合，还是在增加优化阻尼？

### 17. 多卡训练一致性

1. 为什么分布式训练里使用了 `SyncBatchNorm`？
2. 当单卡 batch 很小时，如果不用 `SyncBatchNorm`，可能有什么副作用？
3. barrier 和更稳的 iterator 重建逻辑在多卡训练里解决了什么问题？
4. 为什么这些问题虽然不在模型公式里，却仍然属于“稳训”的一部分？

### 18. checkpoint 与资产管理

1. 为什么训练时要同时保存完整 checkpoint 和 `ema_only` checkpoint？
2. 完整 checkpoint 和纯权重 checkpoint 分别服务什么场景？
3. 如果只保存完整 checkpoint，后续使用链路会多出哪些心智负担？

### 19. loss 配比与多任务平衡

1. 为什么这个项目重新调整了 `center / offset / height / lwh / yaw` 的损失权重？
2. 为什么 `center_loss` 和 `yaw_loss` 被显式提高？
3. 为什么 `lwh_loss` 在这个项目里反而被压低？
4. 如果总 loss 在下降，但可视化结果不好，你会怀疑哪一类子 loss 配比有问题？

## 四、模型层题

### 20. 整体建模思路

1. 这个项目的 BEV 表示是完全隐式学出来的，还是带有显式几何先验的？
2. 为什么单目到 BEV 的问题不能完全依赖“网络自己猜”？
3. 你怎么概括这个项目在“显式几何”和“学习能力”之间的平衡？

### 21. 几何 lifting 方式

1. 为什么这个项目不是先显式估深度再做 lifting，而是直接按离散高度平面采样？
2. `_compute_sampling_coordinates()` 这一步的本质在做什么？
3. 相机内参在从图像特征投影到 BEV 特征时起到了什么作用？
4. 你怎么向面试官解释 `grid_sample` 在这里承担的角色？

### 22. 多高度平面

1. 为什么不是只投一个地面平面，而是投多个高度平面？
2. 多高度平面相比单平面能补充什么信息？
3. 为什么这个项目没有走完整 3D 稠密体素，而是选择少量离散 plane？
4. 这反映了项目怎样的算力与表达能力折中？

### 23. 几何采样与语义融合解耦

1. 为什么先 `grid_sample` 做几何采样，再交给 `BEV neck` 融合？
2. 如果采样后直接接检测头，最容易出现哪些问题？
3. 把“几何对齐”和“BEV 语义融合”拆成两步，对训练有什么帮助？
4. 这种模块解耦对后续替换 backbone 或 neck 有什么好处？

### 24. yaw 表达方式

1. 为什么 yaw 不直接回归角度值，而是回归 `sin / cos`？
2. 直接回归角度在边界处为什么会不稳定？
3. 为什么还要先对预测的 `sin / cos` 做归一化，再算 cosine similarity loss？
4. 这种做法相比角度离散分类有什么优势和劣势？

### 25. 检测 head 与输出定义

1. 这个项目的检测输出通道是怎么组织的？
2. 为什么 `center / offset / height / lwh / yaw` 这组定义适合当前任务？
3. `DET3D_OUT_CHANNELS = 27` 是怎么来的？
4. 为什么项目当前把类别空间收敛到 `vehicle / person / cyclist` 三类？

### 26. 分割分支

1. 这个项目里的分割头是挂在图像 backbone 特征上，还是挂在最终 BEV 特征上？
2. 为什么分割分支和检测分支没有完全共用同一个输出头？
3. 你觉得当前这种设计更偏“共享 backbone，分开任务头”，还是更深度的多任务耦合？

### 27. 解码与后处理

1. 检测预测结果最后是怎么从 heatmap 和回归量解码成 3D 框的？
2. 中心点解码为什么还要做点级别 NMS？
3. `atan2(sin, cos)` 在 yaw 解码里解决了什么问题？
4. 如果中心点阈值调得太高或太低，最终结果会出现什么现象？
